## オーナー向けの要約

対象は 11-13 20:10 に公開された版です（UI 8849bf9・米国 11-12 のデータ）。実測の件数は、手元で再現した掲載 980 行・準備 37 行のものです。公開版の 998 行・43 行の銘柄名は 未検証 です。

**実測**

- **準備がそろった 37 行。** チャートで確認した結果は、すぐ買える形 1件（IDT）、監視 7件、見送り 29件でした。
  - 見送りのうち 8件は、値動きが張り付いた銘柄です（PCRX・BWIN・TECH・ARX・CEPO・DSGR・PRTH・RNW）。
  - PCRX は 10/8 に +44% の窓を開け、その後の 25 営業日は終値が 36.31〜36.49 にとどまっています。それでも候補の 7 行目に「買いゾーン」として、244株の試算付きで出ています。
- **「ブレイク失敗」21件のうち 7件は誤りです。** ピボットができる前の上抜けを数えていました（MGRC・TMP・CZFS・TBCH・OABI・JILL・ASO）。保有者には誤った売りのサインになります。
- **SEC の読み取り失敗 112件（PayloadMismatch）。** 受け取った記録の CIK が整数でなかったことが原因です（コードと件数からの推論）。
  - 数字の文字列だったなら、修正で回復します。
  - CIK が欠けていたなら、回復しません。
  - どちらであるかは 未検証 です。
- **「EPS 2/342/431」は 25% 基準の数ではありません。** Code 33 の EPS 加速の数です。第4四半期の EPS を報告しない企業では、加速は合格になりえません。
- **1440 の最初の表示が遅い原因（最長 250ms、予算 200ms）。** 右ペインのチャートで、移動平均の名前の置き場所を探す処理です。ラベル改修の第3〜4回で、この処理がおよそ倍になりました。

**未検証**

- 公開版の銘柄の内訳と決算日。
- 第4四半期の参考値の精度。
- 修正の実データでの効果。次の定時公開を読んでから報告します。

## 否定された指摘（3件・すべて p4 の一部の主張）

- **「PCRX は地合いだけで買いゾーン内を免れている」は誤りです。** 地合いが良くても、判定は「出来高不足の上抜け」で待ちになります。
- **「試算は地合いを読まない」は誤りです。** 試算は「試算のみ／目安 0%」を出しています。
- **「一つの状態に二つの名前がある」は誤りです。** 「弱含み」（独自判定）と「調整」（バックエンドの局面判定）は、出どころを示した別々の判定で、違いも画面で説明しています。

## STEP 0（最初に・一人で）

既定の合成データの 30 銘柄は変えません。そのため、492 表示のプローブ、Today の件数、高さの台帳は動きません。

**検証用の合成銘柄（使う spec だけが有効にする）**

| 銘柄 | 形 |
|---|---|
| ZZRL | RS線あり・新高値 |
| ZZRW | RS線あり・高値から下 |
| ZZHB | 上抜け後に保った銘柄。緑の矢印。週足の型で、ピボットの足は週の途中 |
| ZZRD | 準備のそろった銘柄。収縮の枠、深さ、出来高の枯渇、静かな日あり |
| ZZPM | PayloadMismatch。received_cik は null（公開と同じ形） |
| ZZNV | 第4四半期の EPS 不明（既存の銘柄をそのまま使う） |
| ZZQF | 第4四半期の EPS 不明。9月の 10-Q があり、算出した Q4 が表示の範囲に入る |
| ZZNR | ピボットより前の上抜け（MGRC の形） |
| ZZPG | 窓開け後の張り付き（PCRX の形） |

- ZZNR と ZZPG は、修正後の期待を `test.fixme` で先に書いておきます。担当のトラックが有効にします。
- ZZHB の緑の矢印は、STEP 0 から検査します。

**共通の部品**

- **ピボットの足を探す関数（`pivotBar`）。** 週足の型では、`se_pivot_date` の週の中で、高値がピボットと同じ足を探します。日足の型では、その日の足です。見つからなければ null で、推測はしません。
- **上抜けの下限を渡す口。** STEP 0 では常に null を返し、動作は変えません。中身は R1 が書きます。
- **値動きの計算（`price_activity`）。** 書き出しから関数に移します。出力は同一です。
- **チャートの描画完了を待つ補助。** `.bc-pulsing` を待ちます。
- **908 件の準備判定プローブ。** round 2 の 28/588 と 23/575 を再現できることを確かめてから、コミットします。
- **作業領域の検証一式。** プローブ、スナップショットの評価、速さの計測、基準値をそろえます。コミットはしません。

## トラック（3つ）

### データ（D）

- **D1 PayloadMismatch。** CIK の比較を厳密にします。整数、または 1〜10 桁の ASCII 数字だけを受け付けます。
  - 同一性の確認そのものは緩めません。CIK が欠けている・null のときは、失敗のままです。
  - 受け取った CIK の種類はログだけに出し、記録には入れません。
  - 回復する件数は、次の公開を読むまで言いません。
  - 単体テスト 39/39。
- **D2 集計の名前の訂正と KPI の分割。** `sec_conditions` の名前を `code33_parts` に改めます。
  - 第4四半期だけが原因の件数（上限値）を加えます。
  - 25% チップの数を加えます。
  - EPS 加速に合格した銘柄名を出します（提出書類で手確認するため）。
  - setup_ready を流動性のある行と、ない行に分けて数えます（再現では 18／19）。
  - 公開している集計ブロックの形は変えません。
- **D3 第4四半期の EPS の参考値（独自計算）。** 純利益を希薄化株数で割って求めます。
  - 判定にも達成にも数えません。
  - 記録への書き込みは止めた状態で出荷します（UI を先に出すため）。
  - 精度はログで測ります。
  - 公開への表示は、オーナーが精度の数字を見てから始めます。
  - 変わる判定は 0 件です。第4四半期で Code 33 が決まる行は最大 103 件、そのうち参考値を付けられる行は最大 21 件です。
- **D4 算出した Q4 の明示。** 算出した第4四半期を引用するところすべてに「Q4算出」と示します。用語も一つにそろえます。

### 準備と結論（R）

- **R1 ピボットの足より後の上抜けだけを数えます。**
  - 対象は、ブレイク失敗、結論、チャートの矢印、ウォッチ、Today。
  - `se_pivot_date` を一覧に加えます（判断7）。
  - 再現では、ブレイク失敗が 21 件から 14 件になる見込みです。誤っていた 7 件が外れます。
- **R2 窓開け後の張り付き。**
  - 窓開けの後の値幅、または ADR が小さい行を「低変動・監視のみ」にします。試算は出さず、一覧の最後に並べます（並び順の変更）。
  - 窓開けより前の土台の安値を、損切りの基準に使いません。
  - 閾値は独自設定で、オーナーが確認します（判断6）。
  - 掲載 980 行と準備 37 行は変わりません。
- **R3 バックエンドの準備判定。** 影響は coverage の KPI だけで、測ってから採用します。
  - `price_pinned` を不合格のチェックにします。
  - ゲート8は、画面と同じステージを見るようにします。908 のプローブで判別力が下がらないときだけ採用します。
  - 新しい診断を3つ加えます。準備判定には使いません。
- **R4 ゲート3・4・6 の代案。** 評価だけ行います。採用はオーナーが判断します。
- **R5（任意）。** 期限を過ぎたブレイク失敗には、日付つきの中立の一文だけを添えます。

### チャート（C）

5項目までに絞ります。配置器の作り直しはしません。どの項目も、492 表示のプローブの差分を毎回の関門にします。

- **C1 速さ。** 移動平均の名前の配置探索を、出力をまったく変えずに軽くします。目標は、実データで 1440 の最長タスク 200ms 以下です。
- **C2 週足の注意書き。** 週足の2行をチャートの中から注記へ移します。ほかのラベルは同一のままにします。
- **C3 320 の安値の価格。** 320 でも、カードに安値の価格を残します。凡例は2行のまま、高さも変えません。
- **C4 ピボットの日付と静かな日。** VCP カードに、ピボットの足の日付と「静かな日 N/10日」を出します。チャートの図そのものは変えません。
- **C5 対ピボットの表記。** 読み取りの「対ピボット」を「±0.1%未満」の規則にそろえます。
