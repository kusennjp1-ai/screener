## 2026-10-02: return explicit pagination to the first candidate

The previous next/previous-page buttons preserved the list's old scroll offset. At the bottom of a 50-row page this left the next page near its end, even though its DOM and order were correct.

Explicit pagination now focuses the new page's first candidate button after React commits its rows. Desktop resets only the internal list scroll to zero and preserves the document position; mobile aligns the candidate heading below the fixed header, keeping that heading and the first row visible. It does not focus a text input, select a stock, recalculate selection rules or change search/sort/CSV inputs. Arrow navigation across rows 50/51 keeps its existing target and focus behavior. All 50 DOM rows, the existing 51px/70px geometry and paint containment remain unchanged.
