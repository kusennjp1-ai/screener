# P1 — 研究インデックスの軽量化・Worker化

実装日: 2026-10-01。実データ: 2026-09-29、5,901銘柄。選定の閾値・未確認の扱いは変更していない。

## 変更とデータ契約

- 機関保有の出典・取得処理・制約文、決算・形状の説明文などは既存の銘柄別詳細ファイルに保持。一覧からは除外した。ただし機関保有の対象期間・公表日・単位は、未公表・古い・異種の指標を合格にしないための検証入力として維持する。
- 一覧は `research-table-v1` の列指向JSON。共通値の辞書、同じ値の列参照、疎な例外を用い、銘柄別ファイルのパスはハッシュと銘柄から完全復元する。欠損、null、false、0を区別する。
- 4手法の並べ替え済み行IDを同じ日次エクスポートで生成。Workerで取得・JSON解析・展開・配分候補の前処理を行い、画面は手法の配列を切り替える。検索・流動性・業種の絞り込みは既存の共通関数を使う。
- 日足の個別再検証では、古い並べ替え・配分キャッシュを再利用せずWorkerで再計算する。処理中に公開世代が変わった結果は反映しない。
- Workerがない環境には互換経路を残す。この環境での性能基準達成は主張しない。

数値を一律に2桁・3桁に丸める仕様は採用していない。例えば24.999999999999996%を25.00%にすると、25%以上という既存条件の結果が変わる。CSV、ピボット、配分の株数にも波及し得る。このため**計算用の数値は完全に維持し、表示時だけ整形**する。情報を失わない圧縮で容量基準を満たした。

## 実測

同じ5,901銘柄、同じNode.js `gzipSync`（既定圧縮設定）で比較。gzip値はファイルの圧縮サイズであり、ブラウザの実転送量ではない。

| 対象 | 変更前 | 変更後 | 基準・結果 |
|---|---:|---:|---|
| 研究インデックス・展開後 | 17,488,569 B | 3,711,168 B | ≤8,000,000 B、合格 |
| 研究インデックス・gzip | 1,757,753 B | 976,503 B | ≤1,000,000 B、合格 |
| 手法ごとの行ID | ブラウザで並べ替え | 上記容量に4手法すべて含む | 別の巨大索引は不要 |

CPU4倍・3回中央値の候補表示≤3.5秒、切替≤400ms、最長タスク≤200msは統合後に付録Aの条件で測定する。容量から速度を推測して合格とは記録しない。採点・axe・4条件の撮影は、画面再構成を含む統合レビューに記録する。

## 検証

`node tools/export-research.mjs` と `node tools/check-data-quality.mjs` を実データで実行し合格。

- 日足検証 1,840 / 1,889、既存の90%基準を維持。
- 全5,901銘柄 × 4手法で、コンパクトデータの**ルール値・状態・根拠を含む判定全体**が銘柄別の正準詳細データと一致。
- 全銘柄・全手法のCSVが正準詳細から生成したCSVと一致。
- 並べ替え済み配列が共通関数の順位と完全一致。
- 共通ピボット、株数、価格、合計リスク、配分額、購入条件の状態が正準詳細での注文試算と一致。
- 詳細スキャンの全件フィルター・並べ替え、AMD / TSM / JPM / KLAC / SLABを含む12件のチャート・詳細、保存履歴・業種集計の既存検証も合格。
- 境界値、欠損とfalseの区別、公表日が未来の機関保有、破損データ、再検証後の無効化、Workerの完了・中止を単体テストで確認。

`npm run lint`: エラー0、既存警告8。全体の `npm run test:run` とブラウザ性能・デザインの最終結果は統合検証後に追記する。対象テストの途中結果だけでタスク全体を完了とは扱わない。

`bd` は実行環境にインストールされていないため、残る計測項目をこの文書で追跡する。
