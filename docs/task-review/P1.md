# P1 — 研究インデックスの軽量化・Worker化

実装日: 2026-10-01。実データ: 2026-09-29、5,901銘柄。選定の閾値・未確認の扱いは変更していない。

## 変更とデータ契約

- 機関保有の出典・取得処理・制約文、決算・形状の説明文などは既存の銘柄別詳細ファイルに保持。一覧からは除外した。ただし機関保有の対象期間・公表日・単位は、未公表・古い・異種の指標を合格にしないための検証入力として維持する。
- 一覧は `research-table-v1` の列指向JSON。共通値の辞書、同じ値の列参照、疎な例外を用い、銘柄別ファイルのパスはハッシュと銘柄から完全復元する。欠損、null、false、0を区別する。
- 4手法の並べ替え済み行IDを同じ日次エクスポートで生成。Workerで取得・JSON解析・展開・配分候補の前処理を行い、画面は手法の配列を切り替える。検索・流動性・業種の絞り込みは既存の共通関数を使う。
- 日足の個別再検証では、古い並べ替え・配分キャッシュを再利用せずWorkerで再計算する。処理中に公開世代が変わった結果は反映しない。
- Workerがない環境には互換経路を残す。この環境での性能基準達成は主張しない。

数値を一律に2桁・3桁に丸める仕様は採用していない。例えば24.999999999999996%を25.00%にすると、25%以上という既存条件の結果が変わる。CSV、ピボット、配分の株数にも波及し得る。このため**計算用の数値は完全に維持し、表示時だけ整形**する。情報を失わない圧縮で容量基準を満たした。

同じ5,901銘柄、同じNode.js `gzipSync`（既定圧縮設定）で比較。gzip値はファイルの圧縮サイズであり、ブラウザの実転送量ではない。

独立した4回目の診断プロファイルでは、チャートの描画コールバックにPC約287ms・スマホ約263msの累積CPUがあり、React同期描画も大きい。これらは初期表示と切替を含む診断区間全体の値であり、切替時間からそのまま差し引ける値ではない。公開データを再取得し、切替時の先頭銘柄が ZETA から IOVA へ変わることを確認した。条件の再計算だけでなく、別銘柄のチャート構築が発生している。

このプロファイルに基づき、次を修正した。

- スマホの候補一覧では、CSSで隠れた詳細欄にチャートを構築しない。親画面の選択銘柄は保持し、詳細へ移る時に正しい銘柄を渡す。詳細へ移った直後のフォーカス、一覧へ戻る操作、別銘柄の表示を検証した。
- 閉じた拡大チャートの全銘柄ナビ配列や現在銘柄を手法切替のたびに構築しない。拡大操作で初めてマウントし、選択銘柄と現行手法を渡す。閉じた間の再計算停止と、再度開いた銘柄の一致を検証した。
- 研究用チャートでは常に空データしか渡していなかったEMA3系列とマーカーを作らない。EPS系列は研究用かつ書籍注記モードの場合だけ省略する。価格・出来高・RS・SMA50/150/200と通常チャートのEMA/EPSは保持する。
- 候補行の価格位置メーターは、同じ形状・描画順・色・ラベルのSVGをまとめて挿入する。挿入する動的値は有限の座標と固定パレット名だけで、文字列ラベルはReactで処理する。
- Worker受信処理には連続するselfサンプルがPC98.1ms・スマホ80.3msあり、受信単位を300件から150件に縮小した。全件・順位・欠損・参照共有の復元を維持する。
