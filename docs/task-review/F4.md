# F4 — ウォッチ銘柄の状態変化通知

## 実装
- 現在の正準 `entryPlan` の価格位置を比較し、日次データの基準日が進んだ際にウォッチ銘柄の変化を端末内の一覧へ保存する。選定・購入条件の合格を通知で代用しない。
- 初回、未確認、古い日足、買収対象、低変動、同日再読込では通知を作らない。イベントIDで重複を防ぎ、Web Locks 対応環境では複数タブの更新も直列化する。
- ローカル通知の許可要求は専用ボタンを押したときだけ行う。許可済みの場合のみPWAの `showNotification` を使用する。通知クリックは同一サイトの対象銘柄へ移動する。
- 場中は既存の接続済みFinnhub受信銘柄かつウォッチ登録済みに限定する。90秒以内の検証済みリアルタイム応答だけを使う。接続キーを受け取らず、配信価格と場中履歴を永続化しない。

## 検証
- `npm run test:run -- src/static/watchNotifications.test.js src/static/components/WatchNotifications.test.jsx`: **8/8合格**。
- 初回抑制、翌日変化、同日/過去日/同時刻の重複抑制、3%と5%の既存手法差、欠損・旧日足・買収・低変動の除外、解除後再登録、接続/時刻/ソース検証、破損保存履歴、通知許可の明示操作を検査。
- `npm run lint`: **エラー0、既存警告8**。
- 全体の `npm run test:run` と公開ビルド・4画面条件・axe・デザイン採点は統合検証担当が別途実施する。OS通知の実許可はこの単体テストで要求していない。端末実機での表示を完了扱いにしない。

## 制約
- サーバーPushはない。アプリを閉じている間は監視・通知しない。日次変化は新しい公開データを開いた時点、場中は既存個人接続で受信している銘柄に限ることをUIへ明示した。
- 保存できない環境はタブ内のみの履歴となり、その理由を表示する。Web Locks非対応環境で同時に別タブを開いた瞬間のOS通知競合は完全な排他保証を持たない。
- 閾値・判定ロジック・自動注文は変更していない。

## 公開前の独立再確認

- Service Workerが使えないデスクトップのNotification経路にもクリック時の銘柄移動を追加。通知URLは現在のアプリURLとURLエンコードした銘柄だけから生成し、クリックするまではページを移動しない。PWA経路は同一オリジン・スコープ内のURLだけを開く。
- 保存履歴には方式も表示し、3%ゾーンと5%ゾーンの方式差を同じ出来事と誤読しないようにした。
- 日次履歴の読み込み前に基準状態を作らないよう、統合ページはデータ取得後にこの部品を初めてマウントする。root担当は通知による同じページ内の銘柄URL変更も反映する。
- 正式な端末通知の許可要求・OS表示は本人の明示操作を待つ。通知クリックのフォールバックはモックで検証し、実機許可済みとの主張はしない。
