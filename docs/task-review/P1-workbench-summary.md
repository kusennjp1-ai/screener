# P1: 日次変化の概要と明細を分離（2026-10-02）

ホーム初期表示に必要な確定件数・業種の根拠・履歴メタデータを `workbench-summary-{hash}.json` に分離した。銘柄ごとの日次変化は、ドロワーを開いたときに元の完全な `workbench-{hash}.json` から取得する。元ファイルの内容、F3 が利用する `current_snapshot`、公開候補の保存契約は変更しない。

## 同一入力でのサイズ比較

ローカルの公開由来データ、基準日 2026-09-29、5,901銘柄、日次変化 7,556項目。Node `Buffer.length` / `gzipSync` によるUTF-8バイト数。gzip値は同じ条件での圧縮実測で、HTTPヘッダー等は含まない。

| 初期読み込みのworkbench | 変更前 | 変更後 |
|---|---:|---:|
| 展開後 | 1,160,555 bytes | 9,399 bytes |
| gzip | 30,530 bytes | 2,485 bytes |
| main threadへ送る銘柄別明細 | 7,556項目 | 0項目（未取得） |

元ファイルは前後とも `workbench-f8b9cfa34603fd8f.json`。研究データの世代は `3841eaefff22a87c61a2ba5be42bb3c2e1eb254c44008827eb2b152798c52452`。初期概要の変更だけで既存の確定件数や明細は再計算しない。ページ全体の性能目標は次の通常CI/Design Acceptanceで測定し、このサイズ削減を操作時間の合格と読み替えない。

## 整合性と欠損

- 新しい概要は原文の形状のままSHA-256検証し、schema、余分な明細、基準日、snapshot、元研究データ世代、完全版への参照を照合する。
- 完全版の取得時は上記に加え、生成時刻、ルール版、対象範囲、比較履歴、全手法の分類件数と実明細数を照合する。クエリキーはpath/hash/snapshot/基準日を含め、キャッシュにも検証を適用する。
- 概要または明細のエラーでは旧selected dataを明示的に消す。読込中や未取得は0件・脱落・空リストとして表示しない。
- 同じ内容のドロワーを再度開くと検証済みキャッシュを再利用する。世代変更中に前日の明細を表示しない。
- 旧manifestには互換経路を残した。Worker内で全文から概要を取り出し、mainへ7,556項目を転送しない。この経路は元ファイルの通信・Worker内解析を省略できない。Worker非対応の旧manifestではmainでの全文解析も残る。新しい公開データでは小さな概要のみを初期取得する。

## 検証

- 対象6ファイル・18単体/フック/exportテスト合格（7.32秒）。新summaryのみの初期取得、ドロワー開閉、再利用、同path別世代、旧世代明細の拒否、取得失敗、schema/items混入の拒否、legacy Workerによる7,556項目の除去、F3保存参照の同一性を含む。
- `npm run lint`: エラー0、既存警告8。ブラウザー回帰specの `node --check` 成功。
- 実データ `node tools/check-data-quality.mjs` 合格。5,901銘柄の選定、CSV、順位、注文計画、12銘柄のチャート・詳細照合、保存履歴、業種、summary/fullのhashと件数が一致。
- root担当のCUAによるPC実操作で、概要から完全版の取得、比較不能1,889件、内訳20件と1/95ページ表示を確認。初回記録を脱落や0件に変換していない。
- PC/スマホの既存 `research-workbench.spec.js` に、ドロワーを開く前の完全版要求0回、開いた後1回、再開時も1回のままで明細が読める検証を追加した。実行は次の通常CIで行う。ローカルPlaywrightは実行していない。
- 選定閾値・通過状態・財務や機関投資家の欠損の扱いは変更していない。
