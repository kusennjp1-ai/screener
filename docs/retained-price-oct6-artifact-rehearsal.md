## Resource and failure bounds

After downloading the originals and installing the arithmetic runtime, require
at least **14,488,193,910 free bytes**:
`8 GiB + 3 * 1,876,607,954 + 256 MiB`. Existing ZIP/runtime storage has already
been consumed at that point. Three payloads conservatively cover restored data,
materialization staging/audits and compiler/checkpoint growth. The existing
restorer's separate 8 GiB reservation cannot be lowered. Every subprocess phase
checks the remaining 8 GiB reserve before starting. After the original executor
was replaced, the exact source ZIP and companion were recovered and rehashed.
The new local executor passed the unchanged physical restoration check with
29,866,377,216 available bytes against 10,466,542,546 required bytes; all original
files were restored and hashed. This source restoration is not a full compiler
or checkpoint pass.

The unchanged existing postcapture supervisor supplies its 95-minute process
ceiling and job-start-plus-100-minute absolute stop, inside a 110-minute job.
The authenticated GitHub job start includes setup before the first command;
installation, boundary tests and retrieval consume this clock. Ten minutes stay
reserved for final recheck, report collection and uploads. Each graph/compiler
phase has an additional fixed timeout. Node uses a 3 GiB heap. Heartbeats persist
every 30 seconds, with the current phase and real elapsed time; failed processes,
timeouts, missing inputs, storage failures and negative validations stay nonzero.

All phase commands inherit the one isolated worker session/process group. A
phase never detaches from the outer supervisor's last-resort group KILL. Before
any child starts, an immutable worker PID/group/session receipt is retained.
Timeout, nonzero coordinator exit, live descendants after coordinator success,
and TERM/INT interruption are terminal: record phase PID, exit code and stop
reason, then signal the proved owned group with TERM and allow at most two
seconds before KILL. The latter includes the worker if descendants ignore TERM.
The outer CLI adopts/reaps orphaned descendants and independently checks the
exact group at return or interruption. It refuses to signal its own group or a
group whose members do not descend from it. Cleanup receipt failures, including
a full disk, cannot prevent termination; remaining console/supervisor evidence
is retained when writable. The execution allowance reserves 24 seconds for both
the existing supervisor's maximum termination waits and final group cleanup,
inside the same 95-minute lifecycle/job-start-plus-100-minute endpoint, preserving
the full ten-minute upload reserve. No timeout is turned into a successful proof.

Real process tests run a Node coordinator, child and grandchild that ignore
TERM, alongside an unrelated witness. They prove complete termination/reaping
for phase timeout, nonzero coordinator exit, worker interruption, outer deadline,
outer interruption and failed cleanup-receipt writes; the witness stays alive.
They also cover a worker that ignores TERM itself, clean successful completion,
and refusal to accept a zero-exit coordinator that leaves live descendants.
If the final KILL prevents the worker from updating a running phase record, the
outer supervisor's nonzero exit/deadline receipt remains the terminal evidence.

These ceilings reuse existing real rehearsal evidence. The earlier failed
postcapture run spent 26m40s in its lifecycle, including 24m06s in incomplete
prepare; its remaining full-cohort phases were unmeasured. Consequently this
first-stage completion time is still unmeasured, and the harness makes no claim
that all phases will fit. It retains phase timings to inform any separately
reviewed future limit change; it never skips a gate to meet its budget.

Diagnostic reports are allowlisted and capped at 128 MiB. The checkpoint is
bounded to 50,000 regular files and 8 GiB logical/compressed bytes. That is a
diagnostic retention bound, not a relaxation of Pages limits. Artifacts are named
`oct6-retained-price-reports-<run>-<attempt>` and
`oct6-retained-price-precarry-<run>-<attempt>`. The latter includes the exact three
original ZIPs and the read-back checkpoint. Neither uses the ordinary
static-site-data namespace or a genuine Static Site combine-and-build identity.
