## Controller-owned direct transport

An isolated module instance executes the exact unchanged collector source. Only
that private instance receives an explicit runtime Session provider; the shared
collector, archive, retention guard and financial validators are not patched.
The strict Session remains a curl_cffi Session for the pinned Yahoo integration.
It accepts only the reviewed GET routes on fc.yahoo.com, query1.finance.yahoo.com
and query2.finance.yahoo.com, limited to the exact selected symbols. Any redirect
is rejected, including same-host HTTPS redirects. This may stop anonymous cookie
bootstrap before a statement is captured; it never authorizes relaxing a gate.

The final native boundary runs after request options and Chrome impersonation.
It enforces direct verified HTTPS, HTTP/1.1, a fresh handle/connection, no reuse,
no redirect, proxy/pre-proxy, DoH, alternate-service routing, client credential,
HTTP authentication, request body, Expect negotiation, early data or library
retry. Request/userinfo/header/session/environment overrides cannot introduce
credentials, unsafe TLS or an unreviewed route. The cookie cache starts in a new
empty ephemeral capture-owned directory outside retained artifacts; preexisting
Yahoo singleton/cache state fails closed. Yahoo logging is disabled so transient
cookies/crumbs cannot enter logs. Owned cache databases close and the directory
is removed even on failure.

The native PREREQ callback reserves and persists an admission before returning
permission for HTTP DO. A second callback in the same perform aborts, as does
admission 1,001, any exception, stale budget, mutation or retention failure.
There is no refund: admitted operations can fail before any HTTP bytes, so the
count is a conservative upper bound, not an exact wire-transaction measurement.
The source argument excludes proxy CONNECT, DoH child handles and TLS early-data
paths, which are not universally covered by PREREQ. Callback references survive
perform/reset; native setup failure has no fallback.
