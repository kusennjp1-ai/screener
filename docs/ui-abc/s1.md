## S1-P1 Lazy stock seam (pure refactor; nothing visible changes)

Status: done. Code: `ebcea738` (variant A kept; see "Variant choice at 1440"). This record follows it and changes docs only.

### What changed

- `frontend/src/static/brief/stockViewLoader.js` (new): the one `import('./StockView')`, with a loaded/failed store like
  `priceChartLoader.js` (`loadedStockView`, `loadStockView`, `stockViewFailed`, `subscribeStockView`). A failed load is retried
  on the next call.
- `frontend/src/static/brief/StockScreen.jsx`: `StockView` is `lazy(...)` under `Suspense`.
  - A module already loaded is handed to `React.lazy` as a thenable that resolves at once, so the screen renders in the same
    pass, with no fallback frame (a plain `lazy(() => import(...))` suspends once even when the chunk is loaded).
  - The fallback is the screen's own loading line 「銘柄データを読み込み中…」 (the same text `StockView` shows before its
    data; no new string), under the desktop header, so the pane keeps its header and place.
  - A failed load resolves to the failure box instead of throwing (see "Deviation" below): 「銘柄の画面を読み込めません
    （通信状態を確認して、再読み込みしてください）」 and a 44 px 再読み込み button that reloads the page, as the chart box's
    does (`PriceChart.jsx`). The desktop header stays above it. If a later load succeeds, the box gives way to the screen.
  - A render error inside `StockView` is not caught: it propagates exactly as on main.
  - The failure text mirrors the chart box's (including its 「再読み込みしてください」). It appears in no yardstick view (no
    view blocks a chunk), so the phrase scan does not see it; it is recovery advice, not a buy recommendation.
- `frontend/src/static/brief/BriefApp.jsx`:
  - imports `./priceChartLoader` (its `loadPriceChart`), so the chart renderer's idle-time prefetch stays in the shell;
  - prefetches the stock chunk in the same idle callback as the market tab's chunk;
  - starts the stock chunk at module start where a stock is on the first screen: at >= 1024 px (the stock pane; this is
    variant A of the order, kept by measurement) and on a stock's own address (`#/brief/stock/…`);
  - on a phone, `open()` navigates at once when the chunk is loaded, and otherwise when `loadStockView()` settles (resolved or
    rejected): the forward view transition never captures a loading screen, and a failed load still reaches the failure box.
    The scroll position is remembered at the tap; only the last tap opens, and none if the screen changed meanwhile; the chart
    renderer's chunk is requested alongside. At >= 1024 px `open()` never waits.
- `frontend/src/static/brief/brief-chart.css`: `.brief-stock-failed` (the chart box's type and button, 44 px at every width).
  The chart box's own rules are untouched.

Design Acceptance (`frontend/tools/design-review.mjs`, 0 edits): the chunk is named `StockView-<hash>.js`, which no Design
Acceptance pattern matches (`/\/priceChart[-.][^/]*\.js/` keeps matching the renderer chunk alone); every selector it reads
(`brief-candidate`, `brief-conclusion`, `.brief-stockhead h2 span:first-child`, `.brief-bar-title b span`,
`.brief-chart-failed`, the candles) is rendered as before. The failure box has its own class, so it is never read as the chart
chunk's failure. The release proof's source markers (`className="brief-stockhead"` in `StockScreen.jsx`, the stock route in
`BriefApp.jsx`) are unchanged.

### Deviation from the order

The order names "a small error boundary". The failure box is reached without one: the lazy component's load resolves a failed
import to the box. Reason: React's development build re-reports an error caught by a boundary as an uncaught page error, which
the static specs count (`expect(errors).toEqual([])`), and a boundary would also catch real render errors of the screen, which
main lets propagate. The behaviour asked for (a failure box with a 44 px 再読み込み that reloads the page) is the same.
