## 3. The two cross-direction decisions (仮の損切り window; 「判定なし」) — written first because they move behaviour

### 3.1 Does the app already compute the provisional stop? (実測 + code)
- **No 損切りに到達 check exists anywhere in the app.** Sell checks are only: strength `day-up`, `week-up`, `up-days`, `climax`; weakness `day-down`, `ma50`, `failedBreakout`, `book` (frontend/src/static/brief/briefSell.js:39-44, sellSignals :243-297, stockSells :353). `grep -rn "仮\|損切りに到達\|損切り到達"` over src/ and tests/ finds nothing in the brief.
- **But the number already exists for most of the stocks concerned, under another name.** positionPlan (positionSizing.js:258-310 (stop at :275)) makes a plan for the buy zone (entry = the close, basis 'price') and for every other position that is not blocked (entry = the pivot, basis 'pivot'); only ext / low / acq / na are blocked (buyGate.js:23-28). stop = entry × (1 − 7/100), a float, printed with toLocaleString 2 decimals (StockVerdict.jsx:12, 170; StockSellCard none). So a stock that crossed and fell back under the pivot (the prototypes' 計画なし case) is, in the app, a 'wait' stock with a plan whose 損切り = pivot × 0.93 = the prototypes' 仮の損切り, labelled as the plan's 損切り（買値＝ピボット）, never 仮の, never judged against later lows.
- 実測 on the 11-12 rebuild (bd20584 snapshot; `git diff --stat bd205842 01066ebe -- frontend backend tools` is empty, so it is main's frontend): script `scratchpad/ui-abc/stop-window.mjs` (app modules via the harness bundle; command in the script header, output `scratchpad/ui-abc/stop-window.jsonl`):
  - 564 listed rows have certified bars and a pivot; 419 have a dated breakout (lastPivotCrossing + breakoutBar, 60 sessions, crossingFloor) — 114 zone, 101 wait, 194 ext, 10 low.
  - 104 of the 419 closed back under the pivot (fell back): **101 get an app plan with basis 'pivot'** (stop = pivot −7%); the other 3 are low-activity rows (plan blocked).
  - The app's displayed plan stop equals the prototypes' half-up cents (Math.round(cents(pivot)·93/100)) on all 233 pivot-basis plans of the rebuild (0 differ). In general it does not always: over every cent pivot 10.00–500.00, 215 of 49,001 display one cent lower (float half-cent, e.g. pivot 10.50 → app 9.76, half-up 9.77; 83.50 → both 77.66). Command: `node -e` loop in this session (toLocaleString vs Math.round(c·93/100)). → if 仮の損切り is adopted, compute it in integer cents, not via plan.stop.
- **Which bar the app would count from.** Two breakout definitions exist: (a) `breakoutBar(bars, pivot, lastPivotCrossing(...))` (breakoutHistory.js:91-125): the latest run's first close above the pivot's cents (touch rule), index = that bar — this is "the crossing the row names" in the prototypes; (b) `pivotBreakout(bars,row)` (bookTechnicalEvidence.js:142-151): the FIRST close above the pivot's cents after the pivot bar (used for the contraction cut and the structural stop). The failed-breakout check and failedBreakoutContext use (a) (briefSell.js:164, 216). A's window = lows of bars index+1..last; B/C = index..last.
- **What A vs B changes on real data (実測, same script):** over all 419 rows with a dated breakout, A hits 59 and B 66. **Scoped to ruling S3** (a zone stock is a plan bought at the close → 判定なし under either window, so the 114 zone rows drop out): 305 rows (194 ext, 101 wait, 10 low) — A hits 58, B 64; **5 flip: ETON (wait, 11/9), FROG (ext, 11/6), STGW (ext, 10/29), XMTR (ext, 11/3), RLAY (wait, 11/6: pivot 18.33, stop 17.05, A low 18.05 (11/12) 該当なし, B low 16.66 (11/6) 該当 — the prototypes' RLAY reproduced with the app's own modules)**; plus USEA (ext), whose breakout is on the analysis day: B 該当, A 判定なし. (CARL flips too, but it is a zone stock.) 5 non-zone rows broke out on the analysis day (CHA, NEXN, USEA ext; TECH, PAYO low). The fell-back rows alone: 104 (101 wait, 3 low), **A hits 55** (B 57) — the rows that would gain a hit if the check enters tally(). 145 of the 564 certified rows with a pivot have no dated breakout in the 60-session look-back (→ 判定なし（上抜けの終値なし）).
